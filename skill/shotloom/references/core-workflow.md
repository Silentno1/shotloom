# Core production workflow

This is a dependency map, not a compulsory paperwork chain. Start at the module that owns the request. Resolve resources within this package and storage through [environment](environment.md).

## 1. Scope, authority and method

Identify the current work/task, approved story version, available evidence and file-backed or conversation-only state. Formal production inherits an approved named-reference or project-authored directing method. Diagnostics and drafts do not require formal approval packets. See [director workflow](../modules/director/WORKFLOW.md) and [method selection](../modules/director/references/director-selection.md).

Read the whole authoritative scope only for whole-work decisions. Preserve hard facts, narrative function and exact execution locks. Reuse unchanged decisions and checks.

## 2. Design before compilation

Direction specifies audience access, playable action, performance, camera/time, sound and endpoint. [Visual design](../modules/visual-design/WORKFLOW.md) specifies appearance, assets and space without defaulting to a house style. Plan representative previs only for real uncertainties.

## 3. Compile and hand off

[Generation](../modules/generation/WORKFLOW.md) compiles each target from the same versioned source lock, with approved references, sound ownership and review criteria. Preserve model-native differences. Missing destination evidence permits a labeled plan, not a submission claim. The user operates the external generator.

## 4. Review actual output

Register a candidate, inspect the actual source/range/modalities, and separate findings from retain/repair/regenerate/unverified recommendations. [Review](../modules/review-continuity/WORKFLOW.md) owns evidence and acceptance records. Missing inspection cannot be filled by a fluent prompt or successful extraction.

Repair recommendations do not accept an unfixed result. Local failures return to their responsible input; structural design failures return upstream. Neither diagnostic advice nor an exhausted attempt budget grants permission to change locks.

## 5. Accept and recompute

Only explicit version-specific acceptance updates canon. Keep earlier records immutable and the active-take pointer separate. Recompute in story order; invalidate affected dependencies rather than treating newer reviews as later story events. See [production state](production-state.md).

## 6. Edit, re-review and finish

[Edit/delivery](../modules/edit-delivery/WORKFLOW.md) selects useful fragments rather than full generated durations. Reconcile retained/omitted events and retiming with review. Use representative temporary sound before picture lock and review normally, silently and audio-only where applicable. Changed cuts invalidate affected finishing and export checks. Packaging never publishes.

Return only the next useful action and required evidence. Handoff records stay in the authorized project location or conversation.
