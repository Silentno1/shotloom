# 导演—剧本适配评分

版本：`director-scoring-20261002`。这是本片决策辅助，不是导演能力榜、历史事实评分、模型成功率或商业成功预测。评分对象始终是“导演/正确署名的作品级参考＋具体作品及方法范围＋当前剧本版本”。同一导演换剧本、换参考作品，分数可以不同；不在公共导演档案里存固定分。

## 触发与比较范围

仅在具名参考路径中需要适配比较，或用户明确要求评分时进入本模块。自建方法不需要导演评分；新作品也不自动触发全库排名。已指定导演只做适配及风险复核，不以全库评分阻止选择。已有锁、普通讨论、每集制作、局部修改不自动启动。重新评分不授权更换方法，锁变更仍按 [director-selection.md](director-selection.md)。自动联合执导未实现。

新作品未限定候选时，用 `all_catalog` 建立当前全库逐人账本（当前 69 档案；数量由目录读取）。每人显示“分数＋适用范围”，或“待评＋欠缺依据”。明确区分尚未研究、已研究但依据不足、已有完整评分；不能把三者都称作“已完成全库评分”。按剧本需求优先深入合理候选，并在推荐前核对不同叙事路径，不能只评自己偏爱的一个人。最终可展开少数可比较者，但完整账本不能漏人；其余待评时称“已评候选中的推荐”，不能宣称全库最优。用户明确只比较若干人时用 `bounded`，保留限定范围出处。库外候选可按正确署名纳入限定比较，不伪装成已入库档案。

只收到大纲，就评价用户明确的完整大纲开发范围，不冒充整剧已读。片段只支持局部分析，不能输出全作品数值排名。不要为了评分启动制作或收费测试。

## 先读剧本、定标准，再看分数

完整阅读当前权威范围，登记项目、作品范围、剧本版本和文本位置；梳理人物驱动力、关系发展、信息释放、关键场面、观看立场、节奏与长线承接。先写五项具体成功条件及权重理由，再对候选评分。模板权重是起点，不是所有题材的固定配方：

| 维度 ID | 判断问题 | 默认权重 |
| --- | --- | ---: |
| story | 能否表达故事核心、主题矛盾和观众观看立场？ | 25 |
| performance | 能否组织人物关系、表演发展及全身行动，而不是只做表情？ | 25 |
| narrative | 能否处理本剧所需的信息、视点、悬念与叙事结构？ | 20 |
| audiovisual | 调度、空间、动作、景别、运镜、声音能否服务本剧关键场面？ | 15 |
| rhythm | 时间处理、段落节奏、单集兑现和跨集积累能否共同成立？ | 15 |

每项为正整数百分比，总和 100。可随剧本需求调整，但须在候选打分前固定；多题材按整部实际承担的叙事任务分配，不按标签数平均，也不能暗中只评最擅长的一场。电影的 rhythm 评价完整段落/全片时间，不强塞集末钩子。同一证据可支持多项，但每项须有不同判断，不能重复以“电影感”加分。

比较使用同一 rubric ID/版本/内容指纹、同一剧本版本、同一目录快照。改变权重/成功条件/比较范围应升版、解释原因、保留旧版依据，再复核全部受影响候选；不得只重算落后者或倒调权重让偏爱的人获胜。指纹只能检测内容变化，不能证明人工先后顺序或读完全文的真实性。

## 评分锚点与未知

五项分别用整数 0–5，按相同锚点评估“在明确改造代价下，这套限定方法有多适合本剧”：

| 分值 | 解释 |
| ---: | --- |
| 0 | 有证据说明根本冲突，破坏该项核心目标；不是未查到资料 |
| 1 | 大部分不适配，需要放弃主要方法或大幅改造 |
| 2 | 局部可用，但明显缺口/改造负担影响重要段落 |
| 3 | 基本适配，有可执行方法，也有清楚限制和常规改造 |
| 4 | 高度适配，关键段落有具体方法支撑，主要风险可管理 |
| 5 | 对本剧该项具有特别强的针对性，证据与反例审查支持；不是“没有任何风险” |

每项记录：剧本位置 → 来源限定事实 → 我们的迁移判断/具体执行 → 分数及理由。导演真实方法来源和本片自主设计分开。只挂访谈链接、类型标签、名气、素材数量、模型方便程度都不是打分依据；模型与预算可列执行风险，不机械扣真人/动画/三渲二的媒介分。不把某导演的单条声音资料当所有维度的证据。

资料不足写 `pending`，分数 `null`，写明缺什么及如何补证；可以保留已知维度，但任一维度待评就没有总分，不以剩余维度重新归一化。全项有依据才算：`总分 = Σ(该项 0–5 分 ÷ 5 × 该项权重)`，满分 100，最多展示一位小数。不使用 86.37 之类虚假精度；小分差只提示回到关键场面比较，不宣称有统计显著性。相同总分并列，不按姓名或目录顺序悄悄选胜者。

## 证据、冲突与推荐必须分列

- 证据可信度 `high/medium/low/unknown` 单列并解释；这是当前支持本次判断的把握，不是导演适配高低。不乘入总分，也不按来源数量自动计算。已评分项必须有足够的已读、可定位、适用该维度的证据；低可信不意味着可以对毫无依据的项硬打分。
- 关键冲突审查单列：`blocking` 为不可接受的核心冲突；`conditional` 为有明确代价或适用条件的风险。每条给剧本位置、冲突、处理办法/用户取舍。高总分不能覆盖 blocking；存在 blocking 者列“关键冲突”区，不进可推荐排序。若选择的实际方法范围避开原冲突，要升版、保留处理依据并重新评估，不能直接把风险删掉让它排名。
- 冲突还没查完，即使五项数字齐全也标“冲突待核”，不给可推荐排名。无冲突也必须写实际检查范围，不能默认空表即通过。
- 完整评分必须有优势、短板/不适合段落、观众体验、改造代价。推荐以这些判断为主，分数为辅助。条件性候选明确带风险推荐，不把“高分”说成无需改造。

可排序不等于值得推荐。若所有候选都不能满足本剧核心要求，应明确“当前无合适推荐”，扩大有依据的研究或交用户取舍；不能只因总有第一名就硬选。没有经过项目校准的统一及格线，不宣称 80 分必然能拍好。新旧评分比较还须注意参考作品范围和证据是否变化，不能把数字升降直接当创作能力升降。

用户可见输出：先说明范围/版本/权重，再给“导演＋参考作品范围｜适配总分或待评｜五项分｜证据可信度｜关键冲突/条件｜主要优势与代价”。有全库账本就明确已评分数、待评数、可推荐数；重点展开少量差异真实的候选，给出首选建议和反例。它不是选择锁：用户指定/认可，或已有明确委托后才按原流程锁定。评分不授权生成、付款、更换画风或恢复暂停。

## 只读计算与字段契约

用 [../scripts/director_scoring.py](../scripts/director_scoring.py) 处理计算、范围和引用检查。它不会阅读剧本、推断导演、自动研究来源或生成艺术评分；实际判断由执行者完成。所有命令只向标准输出返回 JSON，不写项目文件。

1. `fingerprint RUBRIC.json`：验证标准并返回指纹。
2. `prepare RUBRIC.json`：按比较范围生成逐人待评骨架，不声称已研究；填入当前目录指纹和 rubric 指纹。
3. `evaluate RUBRIC.json ASSESSMENT.json --authority CURRENT_AUTHORITY.json`：对照从现行项目权威独立读取的三项信息，再检查并计算；不能从待检旧表抄出“当前”权威。没有新项目权威文件时先在已授权的选型记录中明确范围，不能虚构已定剧本。

rubric（JSON 对象）：

- `schema_version: 1`，`id`、`version`、`basis` 为非空文本。
- `authority: {project_id, work_scope, script_version}`，三项非空；`reading_scope: complete_authoritative_scope`，`script_sources` 为全文来源/版本位置的非空文字列表。
- `criteria` 恰好 story/performance/narrative/audiovisual/rhythm 五键；每项 `{weight: 正整数, need: 本剧成功条件, rationale: 权重理由, script_refs: [实际位置]}`。
- `comparison: {mode: all_catalog, reason: 范围依据}`；或 `{mode: bounded, reason: 限定范围及出处, profile_ids: [不重复的有效 ID]}`。库外 ID 为 `external:<slug>`，不得重用退役 ID。

assessment：`schema_version: 1`、`id`、`version`、`rubric_sha256`、`catalog_sha256`、`candidates`。骨架仅提供状态；不要把占位提示当完成依据。修改判断应升 assessment 版本，保留旧版记录（写入位置遵守用户项目规则，不由程序自动落盘）。每个 candidate：

- `profile_id`，`name`（库内使用该档案的中文名或英文名；库外已评分项必须换掉骨架 ID 占位名，并核署名）；`research_status: not_reviewed|reviewed`，`pending_reason`（存在待评项时必须）。只有确实检查过才用 reviewed。
- `reference_scope: {works: [具体作品], boundary: 季集/段落/方法边界}`；无评分的未研究项可为 null。
- `evidence: [{id, source, locator, work, claim, limits, checked_at, kind, supports: [维度 ID]}]`；work 在该候选作品范围内，日期 ISO YYYY-MM-DD。kind 为 creator_account、collaborator_account、production_primary、work_observation 或 critical_analysis。claim 是来源事实，limits 是证据限制，supports 由读过来源的人判断，不能自动按卡片数量生成。库外已评分者另有 `credit: {source, claim}` 说明已核署名。
- `dimensions` 恰好五项，每项 `{status: scored, score: 0–5 整数, rationale, adaptation, script_refs: [...], evidence_ids: [...]}`；待评项 `{status: pending, score: null, reason}`。
- `confidence: {level: high|medium|low|unknown, rationale}`；有已评分项时不能 unknown，且 research_status 必须 reviewed。
- `conflict_review: {status: complete|pending, summary}`；`conflicts: [{severity: blocking|conditional, issue, script_refs: [...], treatment}]`。空列表不免除审查说明。
- 五项完整时须有非空 `strengths`、`weaknesses` 文字列表，`viewer_experience`、`adaptation_cost` 文本。它们不是新增计分项。

输出保留逐人依据，并给 score/status/rank、分组和覆盖计数；待评/冲突未核/关键冲突均不进推荐排名，同分并列。输出标记 `workflow_scope: diagnostic`、`automatic_selection: false`、`production_authorized: false`；不能把它当生产交接包。程序能检查声明、运算、引用与版本一致性，不能认证引用真实性、完整阅读、署名真伪、实际源资料是否支撑判断或成片质量。运行 [../scripts/test_director_scoring.py](../scripts/test_director_scoring.py) 的合成数据测试，只证明这些约束；不得把测试分数移入真实项目。
