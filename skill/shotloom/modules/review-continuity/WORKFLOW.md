# AI Drama Review and Continuity

Review the actual object the user named. A prompt review is not a video review; technical metadata is not visual approval.

For production acceptance, inherit the current authorized director-style selection and matching `director_style_ref` under [director-selection.md](../director/references/director-selection.md); validate new/changed handoffs with `../director/scripts/director_style.py check PACKET --stage review`. Missing/stale selection does not block targeted diagnosis, but blocks formal acceptance and dependent canon propagation. Inspect actual acting, viewpoint, space, timing, edit and sound against the chosen method and intended audience effect, including neighboring shots where material. Distinguish purposeful variation from accidental drift and superficial signature imitation; do not count famous shots as style success. A name, prompt or structural pass does not establish realization.

## Scope and evidence reuse

- Distinguish asset review, targeted media inspection, full take acceptance and continuity updates. A question about one defect does not request a full acceptance review or a ledger write.
- Establish file/version and criteria from the request or existing evidence; ask only when missing information changes the verdict. Reuse evidence only for the same source content, review range, settings and relevant acceptance baseline. Re-extract changed or insufficient ranges, not the entire set by default.
- Read only references for the selected review. Generated evidence files require the task's write authorization; an explicitly read-only task uses available evidence and reports what cannot be checked without new artifacts. Never substitute absence of evidence with approval.
- Keep explicit acceptance and ledger-write authorization. Reuse an already explicit, version-specific acceptance where applicable; do not infer acceptance from a casual positive comment. Handoffs follow the user-selected storage policy; machine-readable continuity records remain in their authorized project location.

## Workflow (select relevant steps)

1. Establish the exact file/version and whether the task is asset review, actual-media review or an accepted continuity update. Route prompt-only diagnosis to `generation`, without initiating a media-review chain.
2. For asset binding, use [references/asset-approval.md](references/asset-approval.md). Record `production_level` and pass it downstream. Discovery remains a candidate until inspected and approved; continuity/formal work cannot bind a pending asset.
3. For media review, use [references/take-review.md](references/take-review.md) and inspect actual frames/audio. For full video or repair/regeneration decisions, apply [references/review-coverage-and-disposition.md](references/review-coverage-and-disposition.md): normal-speed coverage of the claimed interval, event/object checks, applicable neighbors and an explicit record of unverified dimensions. Do not treat tolerance for minor defects as permission to skip looking. For video/audio needing new technical evidence, run `scripts/take_preflight.py` once; reuse sufficient existing output. Add targeted `--dense-range START:END --dense-fps FPS` where temporal changes need closer inspection; use `--dense-sampling all` for every decoded source frame in a bounded critical interval. Inspect native-resolution individual frames for fine detail, not just the sheet. Choose density from the actual source/event and read returned source timestamps and detector status. Default 24 is not proof that every source frame was inspected; neither is successful all-frame extraction proof that the frames were reviewed. Use `--selected-out` for a fragment's exclusive source outpoint; distinguish it from the true file tail and rendered cut endpoint. Still-image review does not need video preflight. Compare native audio with its ownership plan when sound is in scope. Actual listening at normal playback is mandatory when judging sound; waveform, transcript and loudness evidence cannot substitute for it. A picture-only review cannot approve the soundtrack or the whole take.
4. Classify findings by severity and salience, then separately recommend retain, repair then review, regenerate the affected unit, or unverified under the active project baseline. Preserve harmless permitted imperfections without inventing a universal zero-defect standard. The optional `scripts/review_coverage_check.py` audits declared ranges, source bindings and decision consistency, never actual viewing or quality. When acting matters, apply the performance review in `references/take-review.md` against the director's contract, checking both insufficient and excessive expression. Apply the correct medium branch; do not force photoreal pore/hair criteria onto stylized animation.
5. When a defect needs diagnosis, use [references/failure-attribution.md](references/failure-attribution.md). If the video plan carries a model-selection rationale, compare its decisive requirements and anticipated risks with the actual reviewed result, alongside normal coverage and unexpected findings; report passed/failed/unverified dimensions in the existing review. This does not require a new selection packet to inspect older media. Recommend one principal variable per retry; executing a rewrite, paid retry or upload requires corresponding authorization.
   Only when reusable learning or skill maintenance is requested/authorized, use [references/rule-learning-and-validation.md](references/rule-learning-and-validation.md) to separate a proposed repair from verified scope and check affected examples. Ordinary take review does not trigger skill edits or a maintenance workflow.
6. Only after explicit acceptance, write continuity using [references/continuity-ledger.md](references/continuity-ledger.md) and `scripts/continuity_state.py`. If an entering baseline changes, stop affected propagation and apply the ledger's resolution policy: re-review, replace, or reuse unchanged acceptance only after exact-baseline restoration; independent paths need scoped evidence.
   For nonlinear contexts, selected-cut changes, withdrawal or resequencing, use [references/narrative-contexts.md](references/narrative-contexts.md). Never conflate presentation order with story order or silently migrate existing project records.

## Rules

- Candidate, rejected and merely discovered media never change registry or current canon.
- Replacing an earlier accepted shot recomputes canon in sequence order; the newest review operation is not automatically the latest story state.
- Recomputed state cannot silently validate old media. A changed entering baseline makes dependent media stale; exact-baseline restoration permits only the bounded reuse in the ledger policy, not a claim of new inspection.
- Actual observed endpoint overrides intended endpoint only after acceptance.
- An accepted local exception remains local unless separately approved as a new rule.
- Automated checks identify review locations; they never auto-accept or auto-reject creative media.
- “Looks better” cannot override hard facts, narrative function or exact locks.
