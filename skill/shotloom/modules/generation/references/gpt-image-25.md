# GPT Image 2.5 生图与编辑

核验基线：2026-10-02。来源与覆盖见 [image-model-sources.md](image-model-sources.md)。这是 OpenAI 官方模型方法，不证明当前 Codex 生图工具或第三方“GPT 生图”按钮使用该型号。

## 型号与操作

官方区分 `gpt-image-2.5-flare`（小模型）与 `gpt-image-2.5-sunburst`（基础模型）。按用户锁定型号和任务需求规划；不能承诺 Flare 一定更便宜，或 Sunburst 在每个任务都更好。需要对照时先取得试验范围/费用授权，不把官方迁移测试建议变成自动批量生成。

分清从零生成、带图参考生成、直接编辑、蒙版局部编辑、多轮编辑；明确哪个输入是基底及每张参考提供什么。多图顺序是输入职责的一部分，不由“参考图”三字自动建立身份优先级。编辑输入必须是实际可用素材，不能只靠历史口头描述。

## 编译重点

- **生成：**用途、主体、空间关系、可见姿态、构图/裁切、已选媒介、材质光色。复杂任务可分段，短任务直接自然语言；没有必须使用 JSON 或神秘词序的规则。
- **人物：**眼神看向谁/什么、身体朝向、手与物件接触、相对大小和身体裁切。不要用“悲伤”“电影感”替代这些控制信息，也不擅改已批准表演。
- **图像编辑：**本次变化与身份、几何、构图、灯光、标识等保留项分开。局部要求明确区域与周边边界，使用实际蒙版时核对入口语义；蒙版和“只改这里”都不构成逐像素保持保证。
- **多参考组合：**逐图分配人脸、服装、道具、背景、布局或风格，指定组合后的位置、比例、遮挡、接触和统一照明。草图/白模可承担布局与透视，不能抢走最终外观权威。
- **文字：**精确内容用引号，说明出现次数、版面位置和层级；必要时单独确认易错拼写。文字正确与美术漂亮分开验收，不因模型支持文字就省掉核对。
- **多格/分镜：**按已批准节拍规定格数、顺序、各格状态及跨格身份，不让模型代替编剧补剧情。静态分镜不证明动作节奏或运镜已经实现。
- **透明资产：**正文说明目标，同时设置真实透明输出参数和格式；检查 alpha、发丝/玻璃/阴影边缘，不将棋盘格背景当透明。

摄影规格是外观线索，不保证物理相机模拟；示例的写实、雨夜、霓虹不是默认风格。严禁因新模型文档而替换项目导演、生产方法或外观锁。

## 官方参数：与正文分开

| 设置 | 本次核验的 2.5 范围 | 防误用 |
| --- | --- | --- |
| quality | auto / low / medium / high / xhigh / max | 不默认 max；同标签不等于两型号效果或耗时相同 |
| size | auto，或合规 WIDTHxHEIGHT | 输出尺寸不代表输入参考图限额 |
| background | auto / opaque / transparent | 透明必须用 PNG/WebP，并验 alpha |
| output_compression | JPEG / WebP 适用 | 不套给 PNG |

自定义输出：每边不超过 3840px、各边为 16 的倍数、长短边比不超过 3:1、总像素 655,360–8,294,400；超过 3,686,400 像素为官方标注的实验性输出。实际宿主可能只露出部分档位，保留原生能力与宿主限制两个层次。

不要从 GPT Image 1/1.5/2 的旧示例复制 `input_fidelity` 或旧分辨率枚举给 2.5。当前指南的该字段解释位于 Earlier models，未由此证实 2.5 可调性；有需要时查 exact endpoint 的当前规格，不补想当然参数。Responses 主模型名称与 image_generation 工具的图像模型不是同一件事。

## 迭代与验收

以最近合格图为编辑基底，优先请求一个主要变化并重申不变项；每轮检查身份、非目标区域和文字是否漂移。需要绝对保留像素时只能把它列为额外合成需求，不能以提示词承诺，也不能未获授权擅自修改原图。

画质不足时先定位是构图、身份、文字、参考冲突还是参数问题；不要一次同时改模型、参考、文案和质量档，使失败无法归因。记录实际输出和成本后才可形成 project-verified 结论。静图通过不能证明转成视频后仍合格；后续视频漂移须在视频步骤独立诊断。
