# User-supplied destination bindings

This replaces a personal host snapshot with a portable verification contract. No provider, account, connector, live catalog or API is required. Shotloom never performs the remote submission.

For prompt-only work, keep a model-native draft plus intended mode/settings and reference roles. If the destination is unknown, use descriptive source IDs, label unresolved syntax and do not claim inputs are attached.

When the user supplies interface evidence, distinguish a user report from direct observation. Record only relevant model/version/mode, reference-label syntax, actual selected file/candidate/version, controls and constraints, observation date and evidence location. A display alias is not the official model ID; never infer an Omni or motion-control branch from a suffix alone.

Compare the plan with that evidence using [operation reconciliation](operation-reconciliation.md). Missing readback remains unverified. A connector echo of intended settings is not independent readback; no account access is necessary to explain the discrepancy.

## No inherited host limits

A prior operator's reference count, prompt cap, duration, model catalog or audio switch cannot constrain another user's destination. Retain official model guidance separately, expose mismatches, and let the user confirm their actual path. Do not erase a documented mode because it was absent from one interface.

Input image geometry is distinct from output ratio; use [reference geometry](platform-routing.md#reference-file-geometry) and its optional local helper only with evidenced limits. Cropping/padding is a new authorized derivative, not a harmless way to make a rejected input pass.

## Returned result

The user provides the actual source and settings evidence when needed. Review measured duration, actual content and accepted state independently; a valid operation plan is not proof of generated quality. This file contains no submission implementation, platform mapping table or billing assumption.
