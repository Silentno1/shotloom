# Wan 3.0 视频：任务、参考与写法

核验基线：2026-10-02，阿里云 Model Studio 官方文档。来源、读取范围和冲突见 [wan-3-sources.md](wan-3-sources.md)。这是模型原生方法，不证明某第三方平台已开放相应入口，也不是项目实测画质结论。

## 先选任务，不先套模板

先确定实际型号（`wan3.0-video` 标准版或 `wan3.0-video-prime` 高速版）、输入模式、已批准的声画目标。文档称两版能力对齐，不能据此保证同一提示词的效果、价格或速度相同。当前文档标为 preview；使用时复核改变决策的事实。

| 任务 | 输入与编写重点 | 不得误用 |
| --- | --- | --- |
| 文生视频 | 无媒体；主体、空间、动作因果、摄影、终点和声音 | 不虚构已上传的 Image/Video/Audio |
| 首帧、首尾帧 | `first_frame`，或首帧加 `last_frame`；描述两端之间的可信运动与状态变化 | 不当成一般风格参考；不无证据承诺仅尾帧模式 |
| 多模态参考生成 | `reference_image/video/audio`；逐项指定借用身份、服装、场景、动作、镜头、音色或节奏 | 参考运动不等于继承原角色、台词、配乐；不自动复制整条视频 |
| 视频编辑 | 源视频 + 改动对象/时间范围/目标状态 + 保留项 | 不把重做整片写成局部修改，不把“保持”当像素级保证 |
| 视频延长 | 源视频 + 接续边界 + 新段因果 + 终点 | 不只写含糊的“向前/向后”，不混淆改写开关与延长任务 |
| 文件或网页转视频 | 指明授权资料范围、目标信息、受众、顺序和已批准叙事 | 不因手册演示可改编就扩写已锁剧本或公开私人资料 |

首/尾帧组与所有 `reference_*`、`file`、`link` 互斥。参考图、视频、音频可互相组合；文件与网页二选一，可与参考组组合。**有音频参考能力，不代表首帧模式可同时带音频参考。**若必须同时精确首帧与参考音色，保留两个要求并说明组合冲突；不得偷偷把首帧改成普通参考图。

## 原生编译方法

1. 从 source lock 独立编译，不翻译 H3/Seedance 成品提示词。支持中文和英文；精确台词、画中文字保留原语言。
2. 简单任务用自然描述；复杂任务按需组织总体目标、参考职责、时间顺序、镜头/动作、台词和声音。不是每条都强制填满标题。
3. 参考组按**各媒体类别独立顺序**绑定 `Image 1`、`Video 1`、`Audio 1`。提交前与真实输入顺序逐个核对；文本写了名称不等于完成上传。不要照抄示例的图片编号。
4. 多镜时写可观察的入点、动作变化、切换理由和出点；时间区间覆盖目标时长、不相互矛盾。单镜明确连续拍摄，区分运镜、构图变化与剪切。官方几秒一镜的建议不是硬性时长，不能把一次打击机械拉长到 5 秒。
5. 对话用清楚的说话者和引号内原话，语气、呼吸、停顿放在台词外；逐人绑定音色，避免多个声音争夺同一角色。精确接触、口型、表演仍须看片验收。
6. 风格、光线和镜头只实现已选视觉合同；手册里的写实、黏土、动漫或慢动作示例不改变项目风格。“1000fps”一类描述只是慢动作意图，不是实际输出帧率设置。
7. 负面约束只写本次必要的排除项，不复制“禁止动画”等会否定已选风格的通用负面词库。避免用大量风格词挤掉动作关系。

## 特殊参考的职责

- **分镜/多格图：**明确它是镜头规划参考而非最终拼图；给出阅读顺序、各格承担的事件与必要转场，补足图中不存在的动作、声音和时间。没有已批准的逐格对应要求时，不强迫一格等于一个等长镜头。
- **白模/预演：**分别指定可转移的空间、遮挡、镜头路径、动作时序；外观来自已批准的角色/美术参考。不把低模质感带进成片，也不宣称能毫米级复制运动。
- **画线运镜图：**说明标线含义、起止位置、经过关系、移动方向和速度变化，成片不保留辅助标线。二维标线是软参考，不是精确三维相机轨迹文件。
- **视频动作/镜头迁移：**指明哪一段、哪一个主体、借用什么、不能借用什么；必要时拆开身份和运动权威，避免原视频服装/脸/配乐污染结果。
- **音频驱动：**区分音色参考、节奏参考、希望保留的音频内容。引用 Audio 不自动意味着整段声音必须复制；不能承诺样本级无损复现。

## 声音所有权

模型可能补充配乐、声效或对白。根据 sound contract 明确允许的原生对白/接触声，以及需要排除的配乐或环境层；需要时写无对白或无背景音乐。不要为了去掉咖啡店环境底噪，把杯子接触声和已批准对白一起禁掉。

`audio=false` 是整个原生音轨开关，不是分轨删除工具。环境声/BGM 为 `post_only` 时不得正向请求它们生成；保留允许的画面动作、同步锚点。若实际入口无法满足选择性声音要求，标注限制并交后期声画方案处理，不能声称“写了不要”就保证干净分轨。

## 参数基线与模式冲突

以下是官方 API 面，不是所有宿主的固定规格；实际输入还须核对当前模式。

- 无参考视频时生成时长 2–30 秒，30fps，480P/720P/1080P；最大值不是制作目标。`duration=-1` 为智能时长，不能用于承诺精确剪辑长度。
- 参考上限：图 10 张；视频 5 段且合计不超过 15 秒；音频 5 段且合计不超过 15 秒。文件或网页最多一个，并遵守上面的组合互斥；不要把所有上限相加后承诺任意混传。
- 实际图片输入：每边 240–8000px，长短边比不超过 8:1，单图不超过 20MB；JPEG/JPG/PNG/BMP/WEBP，PNG 不支持透明通道。对需去透明的素材先确认底色和派生图权限，不直接拉伸或裁掉关键区域。
- 实际视频输入：MP4/MOV，每段 1–15 秒，总时长不超过 15 秒，至少 16fps，每边 240–4096px，比例不超过 8:1，单段不超过 100MB。
- 音频输入：WAV/MP3，每段 1–15 秒，总时长不超过 15 秒，单段不超过 15MB。
- 提示词上限 20,000 字符，文档按每个汉字或字母计一字符，超出会截断；不推广为其他模型/宿主的限制，也不为接近上限而灌水。
- `prompt_extend` 是提示词改写，默认开启；`file/link` 要求开启。与“视频延长”不是同一开关。严格锁定任务需评估改写风险，但不能违反该模式的必需条件。
- 使用文件/网页前核实具体文件格式、页数、大小和访问权限。官方公网 URL 输入要求不是公开用户私有素材的授权。

### 延长时长的保留问题

API 参数说明把有参考视频时的“输入视频合计 + 输出时长”限制为 30 秒；提示指南又建议延长时把 duration 设为输入加预计新增时长，或设为 -1。不能由此猜测返回文件必然包含原片还是只含新段。

计划中分别写清**源片长度、希望新增的长度、希望的最终成片长度**，用“接在原片最后一帧之后 / 补在第一帧之前 / 两端扩展”消除方向歧义。提交前依据具体入口澄清 duration 口径；未澄清时保留创意计划，但不得承诺精确延长输出或为验证擅自消耗积分。`usage.duration` 也不能直接当成最终文件长度；实际出片后读真实时长并看片确认拼接。

## 提交与复盘

没有宿主时仍可交付上述原生任务计划；有授权提交时再绑定实际槽位、参数、费用与素材。任务已有 ID 时查状态，不因等待/未知状态自动重提。输出检查参考身份、时序、接触、镜头、声音和终点；文档支持不等于项目已验证。没有这一路径的专用语法验证器，不把 `--platform generic` 的结果包装成通过。
