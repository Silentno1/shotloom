# Shotloom

简体中文 | [English](README.md)

**以审核与迭代驱动 AI 影视制作的导演 Skill。**

Shotloom 是一个面向 AI 电影、短剧和漫剧制作的开源导演 Skill。它帮助智能体把剧本与创作意图转成分镜方案和模型提示词，审核实际返回的素材，再将修改决定落实到后续镜头与剪辑中。

你可以用它推进一段完整的制作流程，也可以只处理一场戏、一个镜头或一次素材审核。它由工作指引、参考资料和可选检查脚本组成，按当前任务读取所需内容。

当前工作版本为 `0.2.2`，尚未发布。最新已发布安装包为 [v0.2.1](https://github.com/Silentno1/shotloom/releases/tag/v0.2.1)。要试用当前目录中的修改，请按下方说明安装完整的 `skill/shotloom` 文件夹。

## 一个小例子

输入：“姐姐用右手把修理铺钥匙交到弟弟左手，说‘店交给你了。’。弟弟先看钥匙，再回答。保持两人共同完成交接这件事的感觉。”

| 交付内容 | Shotloom 会把什么说清楚 |
| --- | --- |
| 剧本与分镜方案 | A 镜展示交接，B 镜留给接收者的停顿。弟弟尚未提供的回答列为待确认，不擅自补台词。 |
| 提示词草稿 | 动作先后、逐字对白、参考素材用途、声音归属，以及“钥匙留在弟弟左手”的结束状态。 |
| 审片记录 | 三张截图能支持可见状态判断，不能证明交接动作和声音正常；这些检查保持未验证。 |
| 迭代记录 | 实际审查并明确接受后，才记录观察到的结束状态。A 镜换版后，B 镜依赖它的连续性需要复核。 |

完整的[文字示例包含分镜和提示词片段](examples/public-workflow/README.md)。这是虚构教材，不是真实生成影片，也不代表已完成实拍或生成验证。

## 怎样工作

1. **明确创作方案。** 整理剧本、导演方法、画面风格和必须保留的内容。
2. **准备生成。** 规划镜头与参考素材，为所选模型编写提示词、设置建议和检查要点。
3. **由用户生成。** 你在自己的工具中完成生成，再把实际图片、视频或音频交回智能体。
4. **审核并迭代。** 根据可检查的证据判断应保留、修复、重新生成，还是暂时无法确认；检查修改对后续内容的影响。
5. **衔接剪辑与交付。** 根据实际素材规划选段、节奏、字幕、声音和后期交接，在具备工具与授权时执行本地编辑。

提示词描述的是制作意图。经审核并明确接受的素材状态，才会成为后续连续性的依据；上游镜头换成新版后，依赖旧状态的部分需要重新核对。

## 可以用它做什么

| 工作 | 典型任务 |
| --- | --- |
| 导演与镜头设计 | 检查场景目的，安排表演与人物调度，比较构图、镜头运动、动作和节奏方案 |
| 视觉设计 | 明确制作方式与画面风格，组织角色、场景、道具和参考素材 |
| 生成规划 | 从同一已确认方案分别编写图片、视频和音频提示词，说明参考素材的用途与未验证设置 |
| 审核与连续性 | 审查实际素材、定位问题，跟踪已接受的状态及其对后续镜头的影响 |
| 剪辑与后期 | 规划带时间的预演和选段，随剪辑调整字幕，校准导出后的声画同步，准备后期交接与成片检查 |

正式制作需要一套明确且经过确认的导演方法。可以参考具名导演或作品，也可以建立自己的本片方法。内置 69 个导演／作品档案及可选检索、适配评分。常规制作继承当前已确认的方法，自建方法跳过导演库；具名研究只检索相关题材或档案，不把整份 JSON 塞进对话。详见[按需读取与兼容说明](docs/PUBLIC-BASELINE.md)。

提示词指导覆盖 H3、Seedance、Seedream、Kling、Wan 及多种图片模型。不同版本和任务的覆盖深度不同，详见[模型路由及覆盖范围](skill/shotloom/references/model-selection.md)。资料带有来源日期，可能变化的能力和限制仍需在使用时核实。

工作指引已随技能保存在本地，安装和普通使用不依赖飞书或在线文档。[Seedance 来源表](skill/shotloom/modules/generation/references/seedance-25-sources.md)记录了访客访问状态、非飞书的官方备用资料，以及来源打不开时的处理方法。

## 快速开始

### 适用的 Agent

Shotloom 面向能够加载 `SKILL.md` 及关联资源的主流 AI Agent 设计。仓库提供 Codex、Claude Code 和通用 `.agents/skills` 目录的安装选项；其他兼容智能体可通过 `--target` 指定其技能目录。

这里说明的是技能加载方式的兼容性，不代表已在每个 Agent 上完成端到端实测。媒体审核和本地执行仍取决于智能体的实际能力。

### 安装

将仓库中的 `skill/shotloom` 完整复制到兼容智能体的技能目录。若拿到的是 `shotloom-版本号.zip`，解压后将其中的整个 `shotloom` 文件夹放入技能目录。

也可以在仓库目录选择一条对应的安装命令：

```bash
./scripts/install.sh --agent agents
./scripts/install.sh --agent codex
./scripts/install.sh --agent claude
```

使用 `--target` 可指定其他目标目录。默认不覆盖已有安装；`--force` 会先保留旧版备份。PowerShell 对应 `.\scripts\install.ps1 -Agent codex`。

所有工作流都包含在这一个文件夹中，无需另装配套技能。不支持技能自动发现的智能体，可以读取 `SKILL.md` 并访问关联资源；只粘贴入口、不提供参考文件，不等于完整安装。`agents/openai.yaml` 是可选界面元数据。

### 从一个具体任务开始

提供本轮目标、相关剧本或素材，以及不能改动的内容。下面四种请求都可以单独使用：

```text
使用 Shotloom 阅读这场戏。沿用我自己的导演方法，先检查人物调度和表演，不选名人导演，不生成素材，也不写文件。
```

```text
使用 Shotloom，把已批准的同一镜头方案分别编译成 H3 和 Seedance 2.5 的提示词。保留对白、画风、声音归属和结尾状态，分别说明未核实设置。
```

```text
使用 Shotloom 审查这段实际视频。说明看过的范围、仍未验证的部分，以及应保留、修复还是重新生成。暂不更新连续性。
```

```text
第一镜已换成新版本。使用 Shotloom 检查哪些后续镜头依赖旧状态，只提出需要复核的部分。
```

上面的文字示例对应当前流程。早期黄金场景作为历史教材保留，从示例页进入，不作为当前版本的验收证据。

## 运行条件与边界

能完成哪些工作，取决于智能体实际具备的能力：

- **对话与完整技能资料：** 可进行创作规划、提示词准备、人工检查指导，并交付可复制的状态记录。
- **项目文件权限：** 可在用户指定的位置保存已授权的记录和交接，不要求特定笔记应用、数据库或固定目录。
- **Python 3.10+：** 可运行结构、版本、连续性和时间计算等辅助检查；没有 Python 时仍可使用文字方法。
- **FFmpeg/FFprobe：** 可辅助读取媒体参数和抽取技术证据，不是安装技能的前提。
- **已授权的本地剪辑或合成工具：** 可执行范围内的预演、剪辑、修复和输出；否则交付可复现的操作方案。

实际素材审核还需要相应的图片、视频或音频感知能力。缩略图不能证明整段运动正常，转录不能代替监听。无法检查的内容必须标为未验证，不能因计算或脚本通过就宣称审片完成。具体规则见[运行环境](skill/shotloom/references/environment.md)。

Shotloom 不调用生成服务、不管理账号、不选择服务商、不上传、不消耗积分，也不自动发布。文件修改和本地编辑遵循用户授权；生成始终由用户在外部工具中操作。

## 开发状态与贡献

当前验证覆盖资源结构、内部链接、规则与计算检查，以及更换目录后的独立运行。测试使用合成资料和本地合成媒体，不调用远程模型；通过测试不代表艺术质量、来源真实性或真实用户批准。

在仓库目录运行：

```bash
python3 scripts/validate.py
python3 scripts/run_tests.py
```

完整的本地媒体检查还需安装 FFmpeg 和 FFprobe，再运行 `python3 scripts/run_tests.py --require-media`。该模式会记录工具版本，任何测试被跳过都会报错。上面的普通模式会说明跳过原因，不能视为完整媒体验证。CI 分为普通环境和必需媒体工具两组；`0.2.2` 的新配置尚待首次远程运行。

当前版本尚未完成真实全片制作验证，也未逐一验证所有智能体环境。PowerShell 安装仍需实际运行确认。详细结果和未验证部分见[验证范围](docs/TESTING.md)。

维护者可在验证完成后运行 `python3 scripts/build_release.py` 生成本地安装包。该操作不会上传或发布，也不会覆盖同名包。
